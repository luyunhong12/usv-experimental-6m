# 悉尼场景运行与操纵验证

## 目的与场景

将中央单机整体转向船放入 VRX 的 Sydney Regatta（澳大利亚悉尼赛艇中心）原始岸景、水面和设施中，验证显示和基本操纵。并非原先只有平面水面的 `usv_hull_trial` 场景，也并非悉尼歌剧院海港场景。

上游输入为 `src/vrx/vrx_gz/worlds/sydney_regatta.sdf`，上游源码不修改。`scripts/prepare_sydney.py` 生成 `src/usv_simulation/worlds/usv_sydney.sdf`，加入原有自定义船和支持燃油质量变化的 `libUsvPhysics.so`。原来静水试验入口继续保留。

## 资源与参数

- 悉尼场景资源使用官方 Gazebo Fuel `openrobotics/sydney_regatta` 第 3 版。本机原缓存 ZIP 中断且不能解压，补齐后要求 ZIP 全文件 CRC 通过，并记录 SHA-256；正式资源解压到 `vendor/fuel/sydney_regatta/`，来源见 `vendor/fuel/SOURCE.json`。
- 其他岸边设施和浮标使用本机已缓存官方资源。每个资源路径/版本及上游场景哈希记录于 `docs/参数与数据/sydney_scene.json`。保留原始模型和作者元数据；悉尼模型的 `model.config` 未列出许可证，本工程不额外宣称资产授权范围。
- 坐标沿用原场景 ENU；地理原点纬度 −33.724223°、经度 150.679736°。船起点 x=−480 m、y=180 m，艏向为世界 +X，z/roll/pitch 沿用当前载荷的静水平衡解。
- 物理步长 0.004 s；燃油、电量、质量、推进与转向参数沿用已有模型。全油整船质量约 1443.213 kg，参数仍是未实测标定的工程估算。
- 本轮无风、波场 gain=0、无水流；原 VRX `coast_waves` 水面网格与着色器保留，初始波场和周期广播均设零波高。移除仅指向 WAM-V 的零风插件。
- 船体浮力尚未接 VRX 时变波场。这是悉尼场景中的平静水面试航，不能作为波浪/风/水流受力验证，也不能当作实船性能测定。

## 启动与操控

```bash
cd /home/yh/Project/usv-experimental-6m/gazebo_sim
bash scripts/run_sydney.sh
```

默认打开 GUI；无需重新导出 Blender 模型。无窗口使用 `bash scripts/run_sydney.sh headless:=True`。启动时重新组合场景，避免复制旧船模型。

另一个终端：

```bash
cd /home/yh/Project/usv-experimental-6m/gazebo_sim
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export GZ_PARTITION=usv_hull_trial
export GZ_IP=127.0.0.1
python3 scripts/drive_boat.py --throttle 0.5 --duration 15
python3 scripts/drive_boat.py --throttle -0.5 --duration 15
python3 scripts/drive_boat.py --throttle 0.5 --steering-deg -20 --duration 20
python3 scripts/drive_boat.py --throttle 0.5 --steering-deg 20 --duration 20
```

逐条执行。正推时 −20° 对应左转，+20° 对应右转，这是船尾推力方向及力臂决定的结果。脚本持续发送控制心跳，结束/中断时零油门、转向回中；船会继续惯性滑行。控制时长为墙钟时间。启动终端 Ctrl+C 退出仿真。不要同时运行使用相同 `GZ_PARTITION` 的另一艘试验船。

## 自动验证方法

`python3 scripts/validate_propulsion.py --sydney --case forward`；其他工况为 `reverse`、`left`、`right`、`reversal`。需要 ROS/Gazebo 环境和本机通信/图形权限。每个工况独立世界/分区，以仿真时间调度：前 2 s 等待，随后油门幅值 0.8；转弯取 ±20°；切换工况在 15 s 切倒车；28 s 停止指令心跳，40 s 结束。

检查实际纵向速度、桨转速、转角跟踪、转向符号、失联停驱、滑行减速、姿态有界、功率/转矩上限、数值有限，以及原生物理质量回执。独立观察相机保存在各工况目录，仅为检查图像，并非船上传感器。轨迹和结果由原始遥测计算，不使用指令值代替实际运动。

结果汇总命令 `python3 scripts/summarize_sydney.py`，只接受所有工况通过后归档到 `docs/参数与数据/悉尼场景验证/`。

## 实施中发现的问题

1. 本地悉尼 ZIP 只有约 20 MB，完整官方第 3 版为 128980600 bytes。使用带长度校验的 HTTP Range 分段补齐，之后逐文件 CRC 校验通过；完整 ZIP 的 SHA-256 为 `ccf768134ff7e7929f67970fd059c0286569bc22ead9d959d45061a5c1ee967a`。下载脚本为 `scripts/download_sydney_assets.py`。
2. 将 `coast_waves` 直接内联进 world 会改变 `SourceFilePath`。上游 `WaveVisual.cc` 用这个路径定位硬编码 DDS 贴图，导致找不到波面法线和天空立方贴图。现使用独立 `coast_waves_calm/model.sdf`，资源链接回原 VRX 目录，保持原始材质而不修改上游代码。修复后重新执行前进测试并人工查看渲染图。
3. 零转角并不等于航向保持：当前工程载荷重心不完全在中线上，推进/阻尼参数也未实船标定，开环前进中存在航向漂移。原因尚未单独定量辨识；本轮只证明可控前后进与左右转向，不宣称直线跟踪通过。接入 ArduPilot 后还需做航向闭环及控制器标定。
4. 初选起点 (−500,160) 的倒车滑行末段接近岸边，出现异常快的减速。为避免地形接触干扰正式操纵数据，将起点移到 (−480,180) 并重跑全部工况；初次探索日志保留在 `log/sydney_validation/development/near_shore_trials/`，不纳入正式通过结果。正式测试加入船体接触传感器，记录收到的接触事件；无事件并不代表完成了所有船体碰撞工况的验证。
5. VRX 初始波场增益必须放在 `<wavefield><wave><gain>`，而非直接放在 `<wavefield>` 下。已同时设置水面视觉和浮标插件的初始值，日志确认初始 gain 与三个波幅均为零；周期广播也保持零。最终配置下重新核对并归档所有正式工况。

## 最终实跑结果

| 工况 | 24–27 秒平均纵向速度 m/s | 约 27 秒航向变化 ° | 结果 |
|---|---:|---:|---|
| 前进 | 1.2403 | -25.893 | 通过 |
| 倒车 | -0.9629 | 13.736 | 通过 |
| 左转 | 0.7743 | 381.227 | 通过 |
| 右转 | 0.7711 | -400.353 | 通过 |
| 前进切倒车 | -0.8474 | -10.958 | 通过 |

五个工况均运行到 40.036 仿真秒，每项获得 391 组推进遥测及对应原生质量回执，所有自动检查通过。正式运行未收到船体接触事件。航向为连续展开角度，因此超过 360° 表示已经转过一整圈；并非传感器单圈角度。上述速度不是最大航速，也不代表实船测定值。

前进切倒车时，指令后 0.524 s 检测到反向桨转速，4.320 s 后船体开始明显倒退（纵向速度 < −0.05 m/s）。该延迟来自推进响应与船体惯性。停止心跳后，所有工况均由失联保护停驱并滑行减速。

桌面 GUI 已打开并确认持续运行，船体、桨舵装置、悉尼岸景、码头、浮标和原 VRX 水面材质可见。现场窗口图通过 XComposite 读取 Gazebo 窗口自身内容，避免其他应用遮挡；观察相机截图也单独保留。
