# 水下推进器转向：实际关节与 Gazebo 画面验证

日期：2026-11-20。用户要求实际打开 VRX，检查左右转向时水下推进器是否偏转，若有问题修复并留档。

## 结论

已实际打开完整悉尼场景的 Gazebo GUI。正常解锁的 ArduRover SITL 经 SERVO1 PWM、JSON 桥和 steering 物理关节驱动水下组件，左转、右转、两次回中均通过；近景中水下电机和桨轴方向确实改变。没有发现关节卡死或推进器网格不随关节运动，因此没有修改船体网格、关节轴、惯性、碰撞或舵机力矩。

本轮复现并修复了另一项实际问题：零推进、左方向杆打满保持时，ArduPilot 识别成 RUDDER 解除武装手势。修复前 DataFlash ARM 记录 Method=0；修复后 `ARMING_RUDDER=0`，正常解锁检查不变，全部阶段保持正常武装直到测试清理。不能据此断言用户此前的 ROS 模式画面问题也是同一原因：默认 ROS 控制没有经过 ArduPilot。

## 实际测试条件和结果

- speed15_concept 船体，静水悉尼世界；没有替换成陆上固定关节演示。
- 独立 Gazebo 分区 `usv_steering_visual_20261120`，飞控 instance 44、JSON UDP 9442、MAVLink TCP 6200；不连接真实硬件。
- 等待 GUIDED 导航可用后切换 MANUAL，正常解锁，不强制解锁、不关闭 ARMING_CHECK。
- 遥控通道 1 依次为 1500→1000→1500→2000→1500；SERVO1_FUNCTION=26。全过程 SERVO3 保持停止（有效输出 1500），以隔离舵机偏转与整船运动。
- 桥映射 `角度=(PWM-1500)/500×35°`，由舵机力矩实际驱动关节，不直接设置网格姿态。速度参考上限 0.15 rad/s、关节速度限制 0.2 rad/s、力矩上限 100 Nm 保持原配置。
- 用末段 2 秒采样检查跟踪误差 <1°、关节与推进器姿态误差 <0.1°；同期读取 `/usv/actuators/state`、`/usv/joint_state` 和 `/world/usv_sydney/dynamic_pose/info`。桨自身轴向旋转不会改变其轴线朝向，因此用轴线方向检查整体转向。

| 阶段 | RC/PWM 请求 | 目标 | 实际关节均值 | 桨轴方向均值 |
|---|---:|---:|---:|---:|
| center_before | 1500 | +0° | -0.0786° | -0.0786° |
| left | 1000 | -35° | -35.0000° | -35.0000° |
| center_between | 1500 | +0° | -0.0786° | -0.0786° |
| right | 2000 | +35° | +34.9627° | +34.9626° |
| center_after | 1500 | +0° | -0.0786° | -0.0786° |

五阶段全部通过，末段关节/网格对照最大误差约 0.000071°。这是仿真内部一致性，不是实物角度精度。零位约 −0.079° 是当前带重力与有限增益的舵机平衡误差，低于验收阈值。

## 修改与采集问题处理

1. `src/usv_ardupilot/config/platform15.parm` 新增 `ARMING_RUDDER 0`，取消方向杆解锁/解除武装手势；使用地面站/MAVLink 明确解锁和解除武装。已有实例若保存过其他值，需确认该参数为 0，不需清空整个 EEPROM。已重建 usv_ardupilot 安装配置。
2. 新增 `scripts/validate_steering_visual.py`，自动采集真实飞控 PWM、关节反馈、网格姿态和 GUI 截图；已有结果拒绝覆盖，可用 `--output` 另存。
3. 首次同步截图服务调用失败，改为独立 Gazebo CLI 调用；PNG 必须完整解码后才复制。截图曾受桌面相机操作影响变成远景，数值检查虽通过，但不能证明可视细节，故固定每张截图的近景相机后重跑并实际审图。探索数据留在 attempts/，没有冒充最终通过证据。

Gazebo 截图服务参数是已有目录，服务成功不代表 PNG 已写完，参见 [上游 Screenshot 实现](https://github.com/gazebosim/gz-gui/blob/gz-gui8/src/plugins/screenshot/Screenshot.cc)。最终使用渲染器原生截图，不采集桌面其他应用。

## 复现

先关闭本检查已有的 Gazebo 窗口，避免同分区出现重复世界；运行下面第一个终端保持开启：

```bash
GZ_PARTITION=usv_steering_visual_20261120 bash /home/yh/Project/usv-experimental-6m/gazebo_sim/scripts/run_hull_trial.sh world:=/home/yh/Project/usv-experimental-6m/gazebo_sim/docs/参数与数据/转向关节与画面验证_2026-11-20/world.sdf headless:=False
```

另一个终端（instance 44 必须空闲，输出目录使用尚无结果的新目录）：

```bash
source /opt/ros/jazzy/setup.bash
python3 /home/yh/Project/usv-experimental-6m/gazebo_sim/scripts/validate_steering_visual.py --output /tmp/usv-steering-repeat
```

脚本会重置专用测试 instance 44 的参数，正常解锁并自动测试；结束后停止自己的飞控/桥接，留下 Gazebo 窗口。测试期间不要同时启动其他执行器控制器。当前检查场景与默认 run_platform.sh 的分区不同，未启动 ROS cmd_vel 控制；常规开船仍使用平台入口。

## 数据与边界

数据目录：`docs/参数与数据/转向关节与画面验证_2026-11-20/`。result.json 是数值判据，visual_review.json 是实际截图审查；arming_audit.json 与 flight_control.BIN 提供修复前后手势原因证据，steering.csv、mavlink.json、json_frames.jsonl 为原始反馈。world.sdf、boat.sdf、platform15.parm、camera.json 是运行配置，build.log 为安装构建结果。

本轮验证零推进下的转向关节及画面同步，没有重新宣称完成全海况操纵或真实舵机硬件认证。推进时前进、倒车、回转的既有验证仍见 2026-11-19 平台报告。此前无法确认画面动作的口头回答，以本次实际观察和数据为准。

检查结束后，专用飞控和桥接已退出，推进指令为零、转向已回中，GUI 检查窗口保留并暂停。若要运行常规 ROS 平台，请关闭检查窗口后使用 run_platform.sh。
