# 15 km/h 工程仿真平台

## 目标与采用的工程方法

用户明确主要用于仿真，暂无实船数据。本轮将项目定位为“有物理依据、参数可追溯、行为可验收的无人船仿真平台”，设计航速 15 km/h。没有实测数据不再作为开发阻塞条件；参数使用 CAD 几何、质量与惯性合成、公开公式、上游模型及明确的工程假设。验收对象是仿真方程/接口/算法的一致性和指定工况下的表现，不是实船性能认证。

保留 6 kW 基准；平台采用独立 speed15_concept 配置（名称保留用于兼容），40 kW 电输入上限、六电池代理、满油约 1780.776 kg。15 km/h 是设计目标，风流、阻力、载荷和电池状态变化后允许出现物理合理的饱和与降速，不用修改物理速度来强行达标。

配置入口：`src/usv_description/config/platform.json`；动力参数：`config/profiles/speed15_concept.json`；飞控参数：`src/usv_ardupilot/config/platform15.parm`。上轮详细物理与话题说明继续适用，但本轮平台入口和验证结果优先。

## 一键启动

在 `gazebo_sim` 目录先执行 `bash scripts/build.sh`。正常运行需要本机 ROS/Gazebo 通信和渲染权限。

```bash
# 悉尼场景 + 15 km/h 工程配置 + ROS 载荷和速度控制，默认波谱 gain=0.3
bash scripts/run_platform.sh
# 无窗口、静水验收工况
bash scripts/run_platform.sh --wave-gain 0 headless:=True
```

另一个终端 source `/opt/ros/jazzy/setup.bash` 后发送：

```bash
ros2 topic pub -r 10 /usv/cmd_vel geometry_msgs/msg/Twist '{linear: {x: 4.166667}, angular: {z: 0.0}}'
```

默认 Gazebo 分区 `usv_platform15`，ROS 默认 domain 继承环境。上述两条启动命令是二选一，不同时运行。启动后不会自动推进；持续速度指令才让船运动。停止发布后停止驱动力，船按阻力滑行。Ctrl+C 清理本次启动的整套进程。任何子进程退出也会结束本套栈，避免留下半套系统。多船/自定义名字与世界仍使用底层 run_sydney.sh 和 run_interfaces.sh，不使用此固定单船入口。

```bash
# 飞控模式：Gazebo + 只读 ROS 载荷 + JSON 桥 + ArduRover SITL
bash scripts/run_platform.sh --control ardupilot --wave-gain 0
```

飞控模式不自动解锁或上传任务；地面站连接 TCP 127.0.0.1:5860。需要本机现有 ArduRover 二进制，或设置 ARDUPILOT_BIN。桥端口 9102 匹配 instance 10。此时不要发布手动推进指令；ROS 载荷进程用 control:=False，不抢飞控控制权。profile 的 EEPROM 与日志分目录保存，baseline 与 platform15 不混用旧参数。暂停/复位后重新启动飞控栈，仍是软同步，不是严格锁步。

## 设计依据和参数不确定性

`analyze_platform_design.py` 对升级工况的静水平衡进行几何裁剪，计算水线长度、湿表面积、无量纲数及功率核算。当前水线长度约 5.743 m，船壳湿表面积约 10.835 m²；在 4.167 m/s、淡水运动黏度 1.004e-6 m²/s 假设下，Re≈2.383e7、Fn≈0.555。

使用 ITTC-1957 `Cf = 0.075/(log10(Re)-2)^2` 得到平板摩擦分量约 244 N。它只用作量级核查，**没有将摩擦分量冒充整船阻力**。当前总纵向阻力代理为 `120u + 180u|u|` N，15 km/h 下为 3625 N，有效拖曳功率约 15.104 kW。浸水正面凸包投影约 0.444 m²，对应当前设计速度的总阻力系数约 0.941；这是把配置转换成无量纲量做审查，不是独立测量。其余兴波、形状、附体等影响没有通过这一公式独立识别，仍包含在工程阻力代理中。

Fn≈0.555 提醒我们高速兴波和动纵倾不能由低速近似精确预测。平台明确使用刚体、局部波面、线性/二次阻力代理来测试控制与系统行为；本轮不声称解决滑行、空化、拍击、动态液体晃荡或流固耦合。这是模型选定的精度范围，后续可按需要替换模型，而非必须等待实船数据。

敏感性范围是工程压力工况，不是统计置信区间或安全海况认证：

- 所有线性/二次平动与转动阻力乘数 0.75、1、1.25。
- 风速 8 m/s，水流 [0.2,0.15,0] m/s，VRX wave gain=0.3；gain 不是浪高的米数。
- 额外 100 kg 集中载荷，位置 [0,0,0.6] m、包络 [1,0.8,0.5] m，重新合成质量/重心/惯性并解浮态。
- 失联、ROS 传感器桥中断、持续转弯和能源降额。

加载附加试验载荷：`bash scripts/run_platform.sh --payload-kg 100`。载荷是一项配重工况，不新增虚构设备外观；启动前求解浮态失败会拒绝生成。允许输入 0–300 kg 不代表该整个范围已测试，当前验收点为 0 和 100 kg。配重改变质量、惯性与静浮态，但不会自动重新识别水动力阻力系数；阻力影响另外通过 ±25% 敏感性工况评估。

## 动力、电池与长时计算

本轮以标称 15 km/h 工况所需约 38.739 kW 电输入，调用与 Gazebo 相同的 C++ EnergyModel，进行两小时、0.1 s 步长的能源独立积分。舵机静态预算 8 W，其他辅助负载沿用配置；电池电流、内阻损耗、温升、SOC、低电降额、发电/充电与耗油均由现有方程计算。

发电机关时约 55.5 分钟开始无法足额提供该功率，约 99.17 分钟推进降至零；开发电机时足额功率阶段约延至 57.5 分钟。两小时算例的最高电池温度约 44.48°C / 43.69°C。实际航速在限功率后应下降，不能把“到停推时间”称为“15 km/h 持续航行时间”。这不是两小时整船六自由度仿真或真实续航预测。发电机和 25 A 充电器远不足以支撑高速电推进。

原始 CSV、实际使用参数和生成的 C++ 计算代码都保留，便于复算；不隐藏保护导致的功率短缺。

## 桨尺寸与碰撞补充

离线脚本新增 `USV_SWEEP_PROFILE=speed15_concept`，按实际 SDF 的 1.5 倍桨几何绕桨局部原点缩放，重新扫查转向 -35°～35°（1°间隔）与桨旋转 0°～355°（5°间隔），共 5112 个组合。未发现新的桨叶/船体表面交叉；唯一重合为原有桨毂与水下电机连接区域，明确列入关节连接例外。

这项验收是离散外部三角形表面相交检查，不包括连续最小间隙、实体包含、柔性结构、齿轮接触和碰撞损伤；原来的运行时正接触测试仍保留，不能只依靠“没收到消息”推断无碰撞。

## 自动航行与故障处理

飞控保持真实单桨整体转向：SERVO1 转向、SERVO3 推进，MOT_VEC_ANGLEMAX=35°，禁用原地转向，设置工程转弯半径；巡航目标 4.166667 m/s，返航速度单独设为 1.2 m/s。地面站失联设置为 HOLD；它意味着停驱后滑行，不意味着船能无推力固定位置。

自动验收脚本 `validate_navigation.py` 连接本机独立 instance 43：正常解锁→上传三航点任务→等待飞控确认 AUTO→LOITER→RTL→GUIDED 离开→停止 GCS 心跳、验证 HOLD。它以实际遥测和运动轨迹判断结果，不能把消息发送成功当作完成动作。LOITER 按船用半径保持定义验收，不承诺位置零误差或固定艏向。

联调中修复了两项流程问题：清空任务的 ACK 不能当作上传完成的 ACK；解锁完成不等于导航滤波器已经允许 AUTO，必须等模式确认。初次按普通车辆设置的转向缩放不适合本船，已改为矢量推力配置。失败或中断的探索保留在 log/platform_validation 的 navigation* 目录，未计入通过数据。

传感器故障恢复的首次测试揭示了过期航向参考问题：桥停止后船按惯性和偏心载荷漂转，恢复时继续追踪旧航向会导致高功率振荡。现已按仿真时间戳拒绝过期 IMU/GPS，并在时钟/通信间隔后重置航向参考和积分；恢复需同时有新鲜导航与持续的新指令。零角速度请求恢复为保持当前航向，不自动返回中断前的航线。

最终 `navigation_v13` 在同一次运行中完成三个航点、LOITER、RTL、GUIDED 离开和 GCS 失联停驱，所有预设判据通过。自动航行最大距离任务折线约 14.065 m（判据 <15 m），存在转弯偏离，不能称为高精度循迹；LOITER 进入 15 s 后的最大位置误差 4.714 m（判据 <12 m），RTL 进入起点 5.987 m 范围（判据 <6 m）。最新桥接下的手动前进、倒车和右转回归也通过：60% 遥控输入工况的取样前进速度约 3.575 m/s、倒车约 −2.862 m/s；它们不是满油门最高速度。任务过程中最高速度 15.169 km/h，不以该瞬时值代替标称稳态速度。飞控共接收 26134 帧，本次最大时间步 0.012 s，无插值追赶或滞后；保存的 DataFlash 记录已审查，未发现 CPUFAILSAFE 解除武装；一秒间隙的插值分步另外由单元试验验证。

早期失联检查按状态文字要求 GCS Failsafe，实际出现 Radio Failsafe。核对上游源码后确认：MAVLink RC 覆盖会刷新 GCS last-seen，不能用于隔离实验；上游 failsafe_trigger 可在处理 GCS 位时打印调用者的 Radio 前缀，文字本身不能证明遥控失联。最终用独立 SITL UDP 遥控输入、SYS_STATUS 遥控健康位、实际 HOLD 模式与零推进命令共同判断；同一完整任务和单独 gcs_isolation 工况均通过。失败记录保留，不改写其原始结论。

早期低阻尼方案和单独提高比例增益的方案均超出航线误差要求，未放宽判据；最终采用较低比例/积分与较强角速度微分阻尼，保留舵机 0.2 rad/s 速度限制和 100 Nm 力矩限制。控制增益是本模型的工程整定结果，不作为任意船舶的通用参数。

### 飞控时间与姿态一致性

探索中 DataFlash 的解除武装原因码确认曾触发 CPUFAILSAFE：桥接跳过的物理状态使飞控仿真时间一次跃进超过 0.2 s。保留飞控保护，桥改为每个舵机帧应答一次；重复帧重发同一应答，重复帧不延长执行器看门狗。相邻飞控状态步长限制为 20 ms，间隙采用位置/速度/IMU 线性插值、姿态最短弧插值；落后物理时间超过 0.1 s 时停驱。Gazebo 仍独立推进，因此这是有界软同步，不是严格锁步，也不把插值当成新增物理计算。时钟回退要求同时重启桥与 SITL。

原生 IMU 四元数相对初始参考姿态，不能直接当成 ENU 世界姿态。桥使用世界里程计姿态，并用机体系角速度外推到 IMU 时间戳；位置用世界速度作同样外推，时间差超过 0.15 s 时拒绝该状态并停驱。NED/FRD 转换在时间对齐后进行。单元验收将一秒间隙分成 50 个有界步长，同时检查四元数归一化、重复时间戳与复位拒绝。

MOT_THST_EXPO=1 用于匹配静态桨推力近似随轴转速平方变化的模型。它是控制端的近似推力线性化；来流、死区和电功率限制仍由推进插件计算，不能据此宣称整个推进器在所有工况均线性。

## 接入覆盖与仍有的边界

- VRX：完整悉尼场景、载荷命名接口、多船命名空间和站点保持评分链路已有验证；不等于所有 VRX 竞赛任务都完成端到端验收。
- ROS 控制：15 km/h 标称、阻力敏感性、载荷、风流浪及故障恢复按本轮工况验证。
- ArduRover：本轮自动航点、LOITER、RTL、失联验收以静水航行为主，LOITER 阶段额外加入水流；不外推到所有波浪/风速组合。单桨整体转向的能力不同于 WAM-V 双推进器，不能承诺原地转向和同等横向控制。
- 数值模型：动力学、耗能、质量变化遵循当前方程的一致性；高航速兴波/滑行、空化、液体晃荡、碰撞损伤和严格锁步尚未实现。仿真输出不作实船速度或续航保证。

## 验证与结果

本轮标称末段速度 **14.989 km/h**，阻力降低 25% 为 14.986 km/h，增加 25% 为 **13.810 km/h**；风流浪工况 14.996 km/h，附加 100 kg 配重 14.995 km/h。持续转弯运行 180.132 s，最大横摇约 7.32°。传感器桥中断后恢复工况约 14.994 km/h。

最终通过结果、判据和图表见 `docs/参数与数据/十五公里平台验证/`。标称速度验收为 15±0.5 km/h；阻力增加等压力工况验收物理约束和稳定前进，同时报告实际速度，不能把降速掩盖成达标。

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
# 以下涉及 ROS 的工况串行运行，测试 domain=74
python3 scripts/validate_platform.py --case nominal
# 其他 case：drag_low、drag_high、weather、payload、command_loss、sensor_loss、endurance
python3 scripts/validate_ardupilot.py --profile platform15 --label manual_control
python3 scripts/validate_navigation.py --label navigation
python3 scripts/validate_navigation.py --label gcs_isolation --failsafe-only
python3 scripts/analyze_platform_design.py

```
