# 六项整改、WAM-V 风格接口与 15 km/h 方案

日期：2026-11-19。所有结果为本机仿真测试，不是实船试航。用户暂无实测参数，要求目标约 15 km/h；保留 6 kW 基准，另建明确标注的动力升级概念工况。

## 六项问题的处理与边界

| 问题 | 本次实现和证据 | 尚不能据此认定的事项 |
|---|---|---|
| 开环直航偏转 | 浮力/推进用明确的世界坐标力矩；水阻速度和作用点统一到固定船体参考。增加 IMU、GPS 反馈的速度/航向控制，静水 1 m/s 末段最大航向误差约 0.0131° | 开环不保证绝对直航；控制器需实船调参，未完成所有海况稳定性证明 |
| 物理参数未标定 | 参数来源保留，新增非负线性/二次阻力拟合入口与原始数据模板；合成数据算法检验通过 | 无实船重量、重心、拖曳/滑行数据，不能宣称完成真实参数标定 |
| 风浪流缺失 | 复用上游 VRX PMS 波谱，视觉/船体同一波参数；随波面浮力、垂向水速、相对水流阻力及风载。独立风、浪、流响应测试通过 | 局部切平面近似；无附加质量、辐射阻尼、破碎浪/拍击或完整 CFD；仅支持 steepness=0 |
| 舵机耗电和断电未联动 | 转向力矩与供电在同一物理步求解；舵机优先于推进分配预算，母线守恒。低电时推进/舵机无驱动力，公开 ROS 载荷传感器停发 | 是集总电气模型，不包含原厂 BMS/CAN、逐设备电源支路、真实启动浪涌；内部仿真真值仍生成 |
| 碰撞和自碰撞 | 启用模型 self_collide，保留四类船体/推进器接触通道；落球确认真实接触消息，左右转向限位与数值稳定测试通过 | 内部齿轮、柔性线束等仍排除；相邻关节体受物理引擎过滤，未做任意碰撞姿态/制造间隙认证、损伤或进水 |
| 移植、版本、多船 | 悉尼资源集中 vendor；按脚本所在目录生成路径；各船话题/TF 命名空间隔离，双船测试通过；缺 CAD 源时可用已保存船壳站位 | DART 动态惯性适配仍固定版本；跨系统须重建并验证，不能直接复制 install 到任意机器 |

## 航速：保持原船基准，增加独立概念配置

| 项目 | baseline | speed15_concept |
|---|---:|---:|
| 推进电输入上限 | 6 kW | 40 kW |
| 静推力模型参数 | 1000 N | 6000 N |
| 零推力进速参数 | 5 m/s | 12 m/s |
| 电池代理数量 | 2 | 6 |
| 标称容量、电压 | 326 Ah，51.2 V | 978 Ah，51.2 V |
| 电流预算上限 | 300 A | 900 A |
| 满油总质量 | 1443.213 kg | 1780.776 kg |
| 桨几何比例 | 1 | 1.5（半径约 0.225 m） |
| 本轮静水运行结果 | 满油门约 5.832 km/h | 闭环目标约 15.001 km/h |

基准运行 70 s，取 50–59 s 稳态窗口。概念配置同样运行约 70 s，速度控制目标 15/3.6 m/s；该窗口电机平均电输入约 38.739 kW，母线平均电流约 777.46 A，峰值电机输入 40 kW。这不是仅改变油门上限：增加四块 76 kg 电池代理、30 kg 电机代理，桨碰撞/质量/惯性随尺寸缩放，重新合成重心、惯性并求浮态。新增电池布置中心 [-0.8,0,0.45] m、包络 [2,0.8,0.4] m 均为设计假设，未确认装配空间。

按当前未标定阻力公式，4.167 m/s 约需 3625 N 阻力平衡力，即约 15.1 kW 有效拖曳功率，因此现有 6 kW 电输入配置无法在此模型达到目标。40 kW、6000 N、桨和电池组合不是已选定真实产品，也不是最低功率选型结论；当前模型尚无高速兴波阻力/滑行/空化校准。4 kW 发电机及 25 A 充电器不能维持高速连续运行，未完成长时热稳态、母排/熔断器/冷却设计。不得把这组数字作为实船采购规格或航速保证。

第一次概念配置开环试跑发生偏航并接近岸边，未作为有效航速证据；最终报告采用闭环航向保持的通过工况。高动力版本的桨尺寸和新载荷需要重新进行制造间隙与实测水动力确认。

## 与 WAM-V 对齐的范围

接入同一 Sydney Regatta 岸景、VRX 波浪、ROS 时钟、TF、标准载荷话题、双船命名空间和原版 StationkeepingScoringPlugin。stationkeeping 测试收到了任务状态和位置误差，证明插件绑定本船；未声称已自主完成任务或所有 VRX 比赛项目兼容。

本船仍是中央单桨整体转向，与 WAM-V 双推进器运动学不同，不能直接复用其左右推进器指令/控制器参数。`cmd_vel` 是本船新增的速度/航向接口，不冒充上游完全相同的驱动接口。

| ROS 话题（usv 可替换为船名） | 用途 |
|---|---|
| `/usv/cmd_vel` | Twist：linear.x 为 m/s，angular.z 为 rad/s；角速度为零时保持接收指令时的航向；持续发送，推荐 10 Hz |
| `/usv/actuators/throttle`、`/usv/actuators/steering` | Float64：归一化轴速请求 [-1,1]、转角 rad；手动指令退出速度闭环 |
| `/usv/sensors/imu/imu/data` | Imu，配置 100 Hz |
| `/usv/sensors/gps/gps/fix`、`/usv/sensors/gps/velocity` | NavSatFix、Vector3Stamped；速度为世界 ENU，配置 10 Hz |
| `/usv/sensors/magnetometer/data` | MagneticField，配置 50 Hz |
| `/usv/sensors/cameras/camera/image_raw`、`camera_info` | Image/CameraInfo，640×360、配置 5 Hz |
| `/usv/sensors/lidars/lidar/scan` | LaserScan，360 点、0.2–100 m、配置 5 Hz |
| `/usv/ground_truth/odometry` | 独立标记的仿真真值，20 Hz；ROS 航向控制不读取它 |
| `/usv/contacts/<collision>` | 四类 Contacts：sealed_hull、hull_detailed_external、azimuth_detailed_external、propeller_detailed_external |
| `/usv/control/state` | time、desired speed、measured speed、heading error、yaw rate、throttle、angle、saturated |
| `/clock`、`/tf`、`/tf_static` | 仿真时钟，world→usv/base_link→传感器；相机另有 optical frame |

传感器频率是 Gazebo 配置频率；ROS 桥接在机器负载下可能丢样，当前自动验收确认消息和 TF 到达，不承诺端到端实时频率。噪声、安装点和舵机参数见 `config/integration.json`，都属估算。公开 ROS 载荷断电门控不抹掉 Gazebo 内部真值或 `/raw` 调试数据；真实感知算法应订阅公开载荷话题，不能用调试真值代替硬件测量。

环境控制：Gazebo `/vrx/current/velocity` 与 `/vrx/wind/velocity` 为世界 ENU 的 gz.msgs.Vector3d，单位 m/s；全场共享。`/vrx/wavefield/parameters` 为原 VRX 波参数。静水测试 wave gain=0；正常启动默认 gain=0.3。gain 是谱幅系数，不是“浪高 0.3 m”。

转向估算：±35°，参考速度 0.15 rad/s、加速度 0.3 rad/s²，最大 100 Nm；电耗为空载 8 W + |力矩×角速度|/0.7 + 0.002×力矩²，最大 150 W。没有真实舵机曲线，后续应替换。

## 启动与控制

在 gazebo_sim 目录，首次或源码更新后 `bash scripts/build.sh`。不同终端使用相同 GZ_PARTITION（默认 usv_hull_trial）。同一分区只启动一个仿真服务器。

```bash
# 终端 1：基准船，悉尼水域，正常波浪；无窗口可追加 headless:=True
bash scripts/run_sydney.sh
# 终端 2：ROS 接口和闭环控制
bash scripts/run_interfaces.sh
# 终端 3：先 source /opt/ros/jazzy/setup.bash，再持续发送 1 m/s
ros2 topic pub -r 10 /usv/cmd_vel geometry_msgs/msg/Twist '{linear: {x: 1.0}, angular: {z: 0.0}}'
```

停止发布后失联停驱；船有惯性会滑行。负 linear.x 倒车，非零 angular.z 请求转弯。执行器能力有限，要求过大时饱和；本轮速度保持只验收静水场景。

```bash
# 概念升级版本，需要先停止上一套仿真及控制；静水重现 15 km/h
bash scripts/run_sydney.sh --profile speed15_concept --wave-gain 0
bash scripts/run_interfaces.sh speed_scale:=4.3
# 第三个终端：
ros2 topic pub -r 10 /usv/cmd_vel geometry_msgs/msg/Twist '{linear: {x: 4.166667}, angular: {z: 0.0}}'
```

双船：`bash scripts/run_sydney.sh --second-name escort`，再分别运行默认接口和 `bash scripts/run_interfaces.sh name:=escort clock:=False`。第二个接口不重复发布时钟。任务评分用 `--task stationkeeping`；此选项只接评分，不自动执行任务。

提供的 ROS 控制器、drive_boat.py 和 ArduPilot 桥对同一分区/船名实施进程锁互斥。要手动脚本控制或飞控控制，ROS 接口必须以 `control:=False` 启动。直接 `gz topic` 属内部调试途径，不受此进程锁约束，不应并发抢控。

## ArduPilot 实际联调

已使用本机 ArduRover SITL、JSON 物理协议完成 MAVLink 连接、正常解锁、前进、倒车、右转和停止。没有禁用解锁检查或强制解锁；初始化期间的 IMU 一致性提示在滤波器稳定后消除。精确结果见归档 `ardupilot/result.json`。自动任务、导航调参和真实飞控硬件尚未验收。

```bash
# 终端 1：基准场景，建议联调先静水
bash scripts/run_sydney.sh --wave-gain 0
# 终端 2：JSON 桥，与下方 instance 10 对应
bash scripts/run_ardupilot.sh --port 9102
# 终端 3：本机已有 ArduRover 二进制，独立日志/EEPROM 目录
python3 scripts/run_sitl.py --instance 10
# 可选终端 4：仅 ROS 感知，不抢飞控执行器
bash scripts/run_interfaces.sh control:=False
```

地面站连接 TCP 127.0.0.1:5860。JSON UDP 为 9002+10×instance，MAVLink TCP 为 5760+10×instance；默认桥脚本独立运行端口为 9002，必须按上例显式匹配。首次想清除该实例 EEPROM 可给 run_sitl.py 加 `--wipe`，此选项会重置实例参数，不是日常必需。

SERVO1 为转向（功能 26），SERVO3 为油门（功能 70），1500 中位，1000/2000 端点；FRAME_CLASS=2。Gazebo ENU/FLU 转为 ArduPilot NED/FRD，电池电压电流同时反馈。这里真值是 SITL 物理后端输入，飞控再生成自己的导航传感器；不等于真实飞控硬件接线。接口是基于传感器时间的软同步，非严格锁步；暂停/性能波动可能触发失联保护，Gazebo reset 后须同时重启 SITL 与桥。

### 旧接触结论更正

本轮检查上游 Contact.cc 发现，当前 Gazebo 接触插件读取 `<contact><topic>`；此前只在 sensor 外层配置 topic，测试可能订阅不到消息。因此旧文档中以“接触消息为零”推断“无持续自碰撞”的部分证据无效，不应继续沿用。现已更正生成器并以落球产生的正接触确认链路可用。离线网格扫碰是另一类几何证据，不能替代运行时接触证明。新的短时通过也不是全船任意姿态碰撞认证。

### 依赖及移植

ROS Jazzy、Gazebo Harmonic；原生惯性适配针对 gz-sim 8.15.0、gz-physics 7.8.0、DART vendor 6.13。VRX commit 7609d1bd90ce7edb29d040a082f949e8b089c864。动态惯性适配保持版本检查，不支持的版本不能绕过检查使用。

ArduPilot 本机源码 commit 1511f27194f1dcc3728270883047bdf022b3fd53；测试二进制 SHA256 b8805e1cfd3fbd661c75bb5b6c620f852d6a8580464f0d037f8f8984e7aadfd6。未修改外部 ArduPilot 源码；它不包含在本工作区内，迁移需设置 ARDUPILOT_BIN 或 --binary。自动验证依赖 vendor/python 中 pymavlink 2.4.49、fastcrc 0.5.0、lxml 6.1.3，vendor 已排除 colcon 扫描。

悉尼资源已集中到工作区 vendor/fuel，模型生成后含本机绝对路径；迁移整个 gazebo_sim 后必须重新 build.sh、prepare_sydney.py/启动脚本生成，再验证。原船 Blender 修改后仍须重新导出；保存的船壳站位回退不是自动同步 CAD。
