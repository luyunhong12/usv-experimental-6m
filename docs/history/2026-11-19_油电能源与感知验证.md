# 油电能源与感知验证

后续更新：本记录描述油电模型首次接入阶段；其中“燃油不更新质量/重心/惯性”的限制已在[燃油质量联动阶段](2026-11-19_燃油质量重心惯性联动.md)解除，原测试数据保留为历史证据。

日期：2026-11-19。对象为当前约 1443 kg 的中央单机试验船；没有新增实船测量。新增 `usv_energy` 包，能源、推进、传感器与文档均在 `gazebo_sim` 内。

## 对应现有设计

既有 `成品交付/03_说明/整船功能说明.md` 和 `成品交付/04_依据与数据/关键设计依据摘存.md` 已确定候选链路：两块 E163 并联 → 电推进及辅助 DC/DC；60 L 柴油箱 → Panda 5000i PMS 候选 → 交流配电 → 25 A 充电器 → 电池母线。独立 12 V 启动电池负责机组启动。

本轮沿用该链路，将原双推进器用电改为当前一台推进器。发电机不是柴油直驱桨，4 kW 交流额定功率也不会变成 4 kW 直流充电：25 A 充电器在约 52–54 V 母线下只能提供约 1.3 kW。充电中仍可能净放电。

## 能量账与联动

每个 Gazebo 物理步按仿真 dt 积分：先计算电池和充电器能提供的电功率及保护降额，再把电机转矩限制到这一预算，最后按实际电输入扣电。不会只让电量数字下降而继续无限推船。

母线满足 `电池端输出 + 充电器直流输出 = 电推进输入 + 已供辅助负载`；电池端电压为 `OCV − I×R`，SOC 由 Ah 积分，充电库仑效率 99.5%。另记电阻损耗、母线净输出 Wh、电推进累计 Wh 和充电累计 Wh。充电会让净输出 Wh 减少，不能把它当“剩余电量”。负轴功率按制动耗散处理，不生成未经验证的回充电量；零速带转矩仍计铜耗。

初始发电机关闭，需人工启动。状态 0=关闭、1=启动、2=预热、3=运行、4=故障。故障码 1=达到残油吸取下限、2=冷却许可丢失、3=启动电池不足。故障后需先关闭再重新启动；许可恢复不会直接自启。冷却许可是模拟输入，并非已经还原原船 PLC、海水流量或发动机温度。

电量不足时先限推，放电保护打开后停推；充电仍可通过独立的充电路径恢复 SOC，达到恢复阈值再允许推进。辅助负载无法满足时记录 `unserved_w`，仪表标记无效。未联动转向关节断电，因此不能把本轮断电结果当完整“全船失电”试验。

## 感知与接口

`/usv/energy/truth` 是仿真内部真值，不应直接当实船传感器输入；`/usv/energy/sensors` 才是模拟仪表，按 1 Hz 采样、约 2 s 电量/电压/电流滤波、5 s 油位滤波。示例固定 SOC 偏差 +0.3 个百分点、油量偏差 +0.2 L；电压/电流/SOC/油量/温度的零均值噪声标准差分别为 0.05 V、0.2 A、0.2 个百分点、0.1 L、0.1℃。随机种子固定以便复现。

油位额外用 `0.5 sin(横摇) + 0.8 sin(纵摇)` L 表示姿态敏感性代理，没有按真实油箱求自由液面或晃荡；输出限制在 0–60 L。满油时偏差和限幅会使仪表短时间仍显示满，不等于没有耗油。带噪声的 SOC 不必逐点单调。传感器失联保留最后数值，但 valid=0，sample_time 不前进、age 增加；消费者必须检查有效性。

低油/低电真值报警是简化系统状态，尚未实现实际液位开关/BMS 的迟滞、CAN 标识和故障协议。控制台明确区分仪表读数和系统状态；ROS 桥接电池/燃油数值使用仪表输出，失联/超时输出 NaN 并产生诊断错误，避免把旧值伪装成新测量。ROS BatteryState 电流正充电负放电，与原始能源话题正放电负充电相反，桥接已转换。

## 复现与操作

在 `gazebo_sim` 目录执行：

```bash
bash scripts/build.sh
bash scripts/run_hull_trial.sh headless:=False
# 另一个终端，仅监视仪表
python3 scripts/energy_console.py --duration 60
# 开发电机并监视；退出控制台不会自动关闭机组
python3 scripts/energy_console.py --generator on --duration 60
# 再一个终端推进
python3 scripts/drive_boat.py --throttle 0.8 --duration 30
# 停发电机
python3 scripts/energy_console.py --generator off --duration 5
# 可选：标准 ROS 2 消息桥接
python3 scripts/energy_console.py --ros --duration 60
```

`--cooling fault/ok` 和 `--sensors fault/ok` 仅用于仿真故障注入。默认 `GZ_PARTITION=usv_hull_trial`、`GZ_IP=127.0.0.1` 用于本机连接；跨机器时必须显式改为可达本机接口地址并配置双方网络。本轮发现启动早期指令发现不稳定，测试改为收到场景遥测后再建立发布器；第一次未送达推进指令的运行未计为通过。

暂停仿真不会消耗能源。重置仿真恢复配置中的初始 SOC、温度、油量和启动电池，并关机、清空积分/传感状态。改变初始油量目前仅改变能源状态，必须另行匹配船体质量工况。

## 尚未覆盖

- 运行中燃油减少不更新船体质量、重心与惯性；只报告 `removed_fuel_kg`。默认短时测试减少质量极小，长航时或不同装油工况需另外更新质量模型。
- 两包按等效均衡电池计算，未模拟单包故障、均流误差、单体电压、老化、容量温度衰减、线缆详细热分布。
- 启动电池仅有 Ah 预算，无冷启动电压下陷/内阻曲线；机组不含真实冷却、转速、机械启动、排气和热故障动力学。
- 充电末段为 SOC 减流代理，不是完整化学/CV 模型；负轴功率不再生；启动维护充电效率与机组轻载油耗未标定。
- 辅助功率仍是固定负载预算，没有逐设备启停、转向伺服力矩电流对应和全船断电动作。

本轮结果用于联调和故障逻辑验证，不作为实船续航、BMS 保护整定或硬件施工认证。优先补测正反车电流/电压/转速、机组不同充电负载油耗、两包独立电流、油位标定表，以及实际启动与冷却许可逻辑。

## 验证方法与复现

- `ctest --test-dir build/usv_energy --output-on-failure`：能量账、充放电、容量边界、低电保护/恢复、热保护、缺油、冷却许可、启动电池不足、无再生制动、仪表失联和重置。
- `ctest --test-dir build/usv_simulation --output-on-failure`：保留推进功率约束、转向参考和浮力解析测试，共 3 项。
- `python3 scripts/validate_energy.py --case drive`；随后串行运行 `hybrid`、`charge_sensor --bridge`、`low_soc`、`fuel_out`。每项实际运行 40 秒仿真。`--bridge` 仅与 charge_sensor 组合使用，启动 ROS 2 测试域 177 的感知桥接验证。
- `build/usv_energy/energy_scenario_report > docs/参数与数据/能源验证/one_hour_scenarios.csv`：4 个独立一小时能源核心算例，dt=1 s，不是额外运行一小时 Gazebo，也没有人为加速耗电。使用 `Parameters.def` 参考默认参数。

低电/低油场景仅在测试副本中注入初始 SOC/油量，默认船模不受影响；这些测试只验能源保护，不验证不同油重下的船舶操纵性。ROS 初测暴露 Jazzy 的 DiagnosticStatus.level 为 byte 而非 Python int，已改用消息常量，并用实际消息订阅复测；失败运行不计入通过结果。
