# 后续集成规划（本轮未实现）

先冻结有证据的船体基线，再做 ArduPilot SITL 最小闭环，最后推进定位融合与 Nav2。当前集成状态不因历史桥代码能编译而改变。

ROS 模式：手动或 Nav2 指令 → ROS 船舶控制 → Gazebo 执行器。
ArduPilot 模式：手动或导航适配 → ArduPilot → 执行器桥接 → Gazebo 执行器。

两种模式共用模型、能源和传感器。同一时刻只有一个执行器控制端；未来要明确指令仲裁、超时、模式切换和紧急停止。不能同时叠加 ROS 航向控制与飞控航向控制。

未来定位融合放 `usv_localization`，Nav2 船舶适配放 `usv_navigation`；开发时才建立，不创建空包假装功能已存在。Nav2 还需处理水面地图、障碍物、坐标系、转弯约束、漂移和制动距离。本轮未新增相关依赖或联调。

## 当前接入门槛

现有 ArduPilot 桥代码和控制权租约保留，历史导航通过记录仅适用于当时版本。本轮不重新联调。接入前逐项核对：

1. 源码、安装插件、实际工况、遥测及验收判据绑定；拒绝静默复用旧结果。
2. 明确持续倒车、自然配平偏航和转向回零的适用范围。不能靠航向闭环掩盖船体发散；既有品质门槛的结果与尚未覆盖工况分别记录。
3. 后续另行选定并构建固定版本的 ArduRover SITL，在冻结船体上核对仿真时钟、ENU/FLU 与 NED/FRD、PWM 中点/正反向和执行器所有权。下载源码只是准备步骤。
4. 再验收解锁、失联停推、重置恢复和低速闭环；飞控与定位稳定后才做 Nav2 任务导航。

最新状态以 [稳定基线报告](../validation/stable_baseline_2026-11-23/README.md) 与 [问题清单](../validation/known_issues.md) 为准；旧 [接入前验收](../validation/preflight_2026-11-21/README.md) 保留历史边界。[ROS 单独运行](../getting_started/README.md) 不需要等飞控接入。
