# Code Supervisor 与人工检查

本轮变更限于部署配方、SITL 启动入口及现有操船验收程序，未修改船体动力学公式。第三方 ArduPilot 源码保持固定提交；不声称其全部上游代码通过本项目检查。

宿主机 full 的构建失败保留；固定依赖容器中重新构建和测试，并核对受检源码一致性。容器命令覆盖配置、工具报告、源码对照和运行数据随结果归档。Dockerfile、忽略规则和 .repos 语义由人工检查；不属于现有 Python/C++ 扫描自动覆盖范围。没有执行本轮 ASan/UBSan、TSan 或变异检查。

| 项 | 结论与证据范围 |
|---|---|
| 1 减少重复决策 | 复用原 run_sitl 和 validate_ardupilot；参数仍由原 ROS 包管理。 |
| 2 基础先行 | 先校验 QGC、源码提交、子模块，再构建与握手。 |
| 3 测试驱动 | 新增部署功能以真实构建/容器/操船验收；不声称先写了失败单测。 |
| 4 需求与职责 | 桥和物理在仿真端；飞控容器不计算第二套船体推力。 |
| 5 质疑前提 | 发现本机依赖升级后改用固定环境，未沿用历史通过结论。 |
| 6 先减后加 | 无新常驻启动脚本，镜像移除构建工具链。 |
| 7 可验证目标 | 正常解锁、方向、回中停推和失联停推有明确判据。 |
| 8 辅助工具 | 临时编排和证据导出工具留在本地；保留有用的现有验收入口。 |
| 9 领域建模 | 区分 PWM 输出、船体速度与航向增量；停推不等于立即停止运动。 |
| 10 边界 | 实例0–99，镜像参数拒绝选项/空白；源码/子模块校验拒绝漂移。 |
| 11 类型 | argparse 保留整数/Path；真实 Docker 与 ArduRover CLI 验证。未执行新增类型专项。 |
| 12 幂等 | 不默认 wipe；试验目录拒绝覆盖，容器名冲突直接报错。 |
| 13 状态隔离 | profile/instance 独立持久目录、参数只读；实例端口仍需调用方互斥。 |
| 14 根因 | 本机失败源于库版本，不伪造软链接或放宽 EXACT。 |
| 15 小步骤 | 先容器启动清理，再手动控制，再失联工况。 |
| 16 行为验收 | 从船体遥测验方向；修复旧右转按绝对航向判断的假通过风险。 |
| 17 Crapper | 本轮未运行 Python CRAP，不能报告相关分数。 |
| 18 Dryer | full 中现有 C++ 重复检查；新增部署内容人工核对无重复参数源。 |
| 19 Mutator | 本轮未执行变异。 |
| 20 重构边界 | 本机启动保留；默认源码/数据目录按新目录约定更新。 |
| 21 工作记录 | 保存构建失败、源与镜像摘要、实际版本和测试结果。 |
| 22 上下文 | 运行证据绑定本轮文件，历史证据不替代本轮飞控验收。 |
| 23 清理 | 仅清理本轮启动的运行进程；保留用户预览和 .vscode 改动。 |
| 24 提交 | 仅提交相关自有代码与文档，不提交 QGC 二进制和上游源码。 |

失联试验同时停止地面站心跳和遥控覆盖，只证明该组合失联后的停推，不能声称分别隔离验证了 GCS、RC、JSON、传感器和电源全部故障。
