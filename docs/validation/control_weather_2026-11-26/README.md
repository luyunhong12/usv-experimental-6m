# 保持协调、风浪验收与物理边界（2026-11-26）

本轮处理四项：有流3 m保持、正反推与换舵协调、5 m/s风及增益1.0波浪验收、无实测条件下的物理可信范围。各项分别记录，不把测试入口完成当作船舶验收通过。正式控制参数暂不改，未接Nav2。

## 步骤一：风浪验收入口

复用 `./usv navigation-test`，新增 `--wind-east`、`--wind-north`（世界ENU，m/s，有限且各分量绝对值≤10）和 `--wave-gain`（0–1）。默认仍为零风零浪。非零风浪只允许完整导航，不与response-only/failsafe-only混用。波浪在场景生成时设置，物理浮力/推进与可视水面共用波谱；风在全部阶段持续发布，包括HOLD和失联阶段，不人为清风来取得通过。

有风浪时保留原25项导航判据，追加5项，共30项：环境遥测覆盖、物理实测风速、非平静波面观测、姿态范围、桨浸水比例。后两项读取既有 `tests/scenarios/environment_acceptance.json`：横摇和纵摇各10°、桨浸水≥80%，没有放宽原阈值。环境覆盖从首个物理样本后5秒到结束，要求最大缺口≤0.5秒且至少10秒；实际风速三个分量必须与输入一致。有浪时局部波面变化必须超过0.01 m。这些是工程筛查，不是稳性或任意海况认证。

生成的运行记录包含环境CSV、风浪设置、原环境判据内容和哈希。原3 m目标保持、手动接管、返航和失联停推仍须通过；外界风浪使HOLD漂移也应如实报告，不能把停推等同位置锁定。

验证：[10项专项单元测试](unit.log)、[Code Supervisor quick](supervisor-quick.log)、[容器构建测试](build-test.log)，后者12个ROS包、12项C++、68项Python及5项接口检查。固定模拟镜像中的未改生产代码重建，当前单元测试和验收helper只读挂载；集成脚本由运行快照提供。[源码哈希](source-sha256.json)、[doctor](doctor-python.json)。本步骤尚不代表实际风浪航行已经通过；full/deep未在此步骤重复执行。

## 控制候选与试验安排

旧日志PIDS显示强流保持的转速目标频繁达到20°/s，而约1 m/s定舵辨识持续转速约9°/s。因此隔离候选只将 `ATC_STR_RAT_MAX` 从20改为8°/s，保留倒车、加速度和其余正式参数；不改变实体舵角、舵机限速、船体阻力或推进力。8是按辨识留余量的试验值，不保证所有油门下都可实现。先跑北向0.30 m/s，过原门槛后才开展多流向推广。

风浪物理敏感性另使用现有性能入口和 `tests/scenarios/weather_uncertainty.json`：同样5 m/s向北风、波谱增益1.0、180秒直接0.3推进请求、零舵，无航向保持；比较名义、船体阻尼×0.75、附加质量×1.25。仅船体阻尼缩放，不宣称附体也同比变化。倍率是离散工程压力测试，不是来自实测的置信区间，不能证明±25%包含真实值。全部覆盖写入独立生成SDF，不修改生产模型。
