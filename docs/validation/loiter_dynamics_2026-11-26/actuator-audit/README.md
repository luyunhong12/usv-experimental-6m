# 执行器时序旁路审计

固定比较MODE=5进入后15–120秒，使用DataFlash的STER、THR、RCOU与仿真propulsion/actuators CSV。每条STER关联此前最近THR/RCOU，最大年龄≤0.15秒；时间用`飞控记录相对首次MODE5的时间+验收loiter事件仿真时间`对齐物理CSV，线性插值。模式通信有小幅时延，因此这是近时诊断，不能称为逐控制周期精确因果重放。

- 请求舵角按JSON桥实际映射：`clip((C1−1500)/500,−1,1)×35°`。与真实关节角度比较RMSE及>10°采样占比，分母为全部1050条合格对齐样本。
- 飞控转向请求取`STER.SteerOut/4500`；横向推进分量代理量取`实际推力×sin(实际舵角)`。桥接和固定舵机轴定义下，该分量符号与NED期望偏航力矩符号一致。**它不是整船总偏航力矩**，没有包含附体、船体水动力等项。
- 异号比例只对`abs(归一化转向请求)>0.001`且`abs(横向推进分量)>5 N`的样本计算；分母写入各JSON，不能当全部运行时间比例。
- 推力符号滞后只对`abs(THR.ThrOut)>1%`且`abs(实际推力)>10 N`计算，排除了过零附近微弱推力，因此不能把这一比例当成全部反推延迟。
- 油门变号计数先丢弃±1%死区内样本，再计相邻剩余符号改变，不设最小驻留时间；不是机械反推次数。
- 目标/实际转速均使用STER的deg/s字段计算RMSE。不同控制策略可能改变目标信号，不能只凭RMSE单独排名控制性能。

| 指标 | 原北向0.30 m/s基线 | 仅收舵预见4秒 |
| --- | ---: | ---: |
| 舵角请求/实际RMSE | 28.32° | 27.77° |
| 舵角误差>10°采样占比 | 43.52% | 39.33% |
| 横向推进代理量与转向请求异号（上述有效子集） | 21.54% | 18.87% |
| 明显推力符号滞后（上述有效子集） | 1.01% | 2.56% |
| 油门死区外变号数 | 9 | 11 |
| 转速请求/实际RMSE | 11.56°/s | 12.64°/s |

仅收舵预见改善位置曲线，但这些执行器指标并非全部改善，故不能称为换向协调已修复。全部数值及各自样本数在同目录JSON，原始CSV无损压缩，输入SHA256绑定结果、物理CSV及DataFlash。
